# 交稿前五项检验

初稿写完再做。内部过，不要把清单贴给用户。一项不过就改，改完从这一项再过一遍，不要只改句子不回头。

脚本能抓住词，抓不住人味和预期。脚本过了不等于能交。

## 1. 词汇检查

抽出全文里的卖点词、程度词、范文词。

硬伤（有一个就改）：打码、马赛克、这张图、图上看不清、绝对值得收藏、真正全面、第一、唯一、永久免费、保证成功、范文产品名（i导航 / idaohang）。

对照事实卡再禁：事实卡「不能说」里的词。视频保存类常见且未获授权时：无水印、去水印、100+、扒主页下视频、二创素材。

频率：神器、安利、亲测——每篇最多各 1 次。小标题「适合人群」不算口癖。

说明书词扫一遍：支持、提供、实现、赋能、闭环、一站式、全方位。出现就把那句改成动作。

## 2. 表达检查

大声读开场 4 段。听着像官网功能页，就重写开场。

问四件事：

- 第一句是不是具体卡住的动作？
- 有没有「我试了 / 今天给大家安利 / 最近在用」这种在场感？
- 数字、按钮、清晰度能不能指到当前图？
- 有没有连续两段只是同一观点换说法？

说明书腔、功能清单腔、评测腔（优缺点表、评分、星级）都不算种草。种草是「我用过，你也可以这样试」。

正文不要讲解制作过程：打码、截图、马赛克、我把标题糊了。

## 3. 预期检查

读者读完会以为产品能做什么。把这些以为列出来，逐条对照事实卡。

把读者可能以为的能力列出来，逐条对照事实卡。事实卡没写的，默认不能说。

视频保存类常见抬高（仅作提醒，以当篇事实卡为准）：

| 读者可能以为 | 先核对 |
|--------------|--------|
| 去水印 / 无水印 | 画面里的字往往去不掉 |
| 100+ 平台 | 只写当下能数的 |
| 把某个号一次下完 | 批量常常只是多条链接 |
| 私密、付费也能下 | 多半只支持公开内容 |
| 永久免费、不限次数 | 次数和价格不编 |
| 商用二发别人的内容 | 版权通常归原作者 |

结尾预期：读者知道去哪个网址、先试哪一步。没有网址（什么值得买 / 知乎可放链的渠道）算预期失败。小红书不能放网址，那是另一套技能。

## 4. 情感检查

痛点虚：用了「很麻烦」「痛点」但没有动作。补动作或删。

热度空：段段感叹、段段「真的香」。留一处「我最近在用」就够。

结尾软：只说「顺了你会收藏」，人不知道去哪。改成打开域名 + 收藏不迷路，或先试一条 + 网址。

结尾凶：马上买、限时、错过没了。改成鼓励。

敌意：点名踩竞品、写得热闹用起来别扭（这种升维句全篇最多 0 次，包括变体）。

## 5. 结构 / 语法检查

- 开场三拍还在。
- 8 节小标题还在（或明确砍成 5 节且编号在）。
- 场景节的平台能对上当前图。
- 没有翻案腔、没有破折号、提示性冒号已清。
- 没有三项同构排比。
- 加粗 3～8 处。
- 图注不泄露制作痕迹。
- 最后一节有网址和「先试一条」类动作。

然后跑：

```bash
python scripts/check.py <稿件.md>
```
